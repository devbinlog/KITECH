# Cell-MES 프론트엔드 사용 시나리오

## 개요

Cell-MES 프론트엔드의 제조현업 업무 흐름 관점 사용 시나리오를 정의합니다.
각 시나리오는 **실제 구현된 기능**을 기반으로 작성되었으며, E2E 테스트 케이스와 1:1 매칭됩니다.

> **마지막 검증일**: 2026-02-08
> **대상 코드**: `app/(main)/`, `components/`, `services/`

# Part 1: 제조 업무 흐름 (Manufacturing Workflows)

## 1. 작업지시 관리 (`/production/orders`)

### 1.1 작업지시 CRUD

**사용자**: 생산계획담당자
**업무 흐름**: 작업지시 생성 → 조회 → 수정 → 삭제

#### 업무 시나리오

**1.1.1 일일 생산계획 수립**
```
09:00 출근 → 작업지시 목록 확인 → 신규 작업지시 생성 → 스케줄 실행
```

1. **작업지시 목록 확인**
   - `/production/orders` → 전체 탭에서 READY 상태 작업 확인
   - 납기일(due_date) 기준 우선순위 판단
   - 긴급 오더 확인 (우선순위 1-3)

2. **작업지시 생성**
   - Lot 번호 체계: `LOT-YYYYMMDD-NNN`
   - 제품 선택 시 자동 라우팅 적용
   - 목표수량, 우선순위, 납기일 입력

**1.1.2 긴급 오더 처리**
```
고객 긴급 요청 → 우선순위 1 작업지시 생성 → 기존 스케줄 재조정 → 현장 통보
```

1. **긴급 작업지시 생성**
   - 우선순위: 1 (긴급) 설정
   - 납기일: 당일 또는 익일
   - 비고에 긴급 사유 기록

2. **스케줄 재조정**
   - `/scheduler/execute` → 긴급 오더 포함 재스케줄
   - 기존 READY 작업 밀림 확인
   - 영향받는 작업지시 납기 검토

3. **현장 통보**
   - 변경된 스케줄 현장 공유
   - 설비 배정 변경 사항 확인

**1.1.3 작업지시 수정/취소**
```
수주 변경 접수 → 해당 작업지시 조회 → 수량/납기 수정 또는 취소
```

1. **수정 가능 조건**
   - 상태가 READY인 경우: 전체 필드 수정 가능
   - 상태가 RUNNING인 경우: 목표수량, 우선순위만 수정 가능
   - 상태가 DONE/ERROR인 경우: 수정 불가

2. **취소 처리**
   - READY 상태만 취소 가능
   - 취소 시 스케줄에서 자동 제외

#### 작업지시 입력 필드

| 필드 | 형식 | 필수 | 검증 | 제조 의미 |
|-----|------|-----|------|---------|
| Lot No | `LOT-YYYYMMDD-NNN` | ✓ | unique | 추적 단위 |
| 제품 | select | ✓ | product_id > 0 | 생산 대상 |
| 목표수량 | number | ✓ | min: 1 | 계획 수량 |
| 주문수량 | number | | min: 0 | 실제 수주량 |
| 우선순위 | 1-10 | ✓ | 1:긴급, 10:저우선 | 스케줄 기준 |
| 납기일 | datetime | | ≥ today | 고객 납기 |
| 비고 | text | | | 특기사항 |

#### 검증 포인트

**데이터 정합성**
- [ ] Lot No 중복 불가 (unique constraint)
- [ ] 목표수량 > 0
- [ ] 납기일 ≥ 오늘 (경고 표시 가능)
- [ ] 계획시작 < 계획종료

**비즈니스 룰**
- [ ] 우선순위 1-3: 긴급 오더 (빨간색 배지)
- [ ] 우선순위 4-6: 일반 오더 (노란색 배지)
- [ ] 우선순위 7+: 저우선 (회색 배지)

#### API 연동
| 동작 | 엔드포인트 | 메서드 |
|------|-----------|-------|
| 생성 | `/api/v1/production/orders` | POST |
| 목록 | `/api/v1/production/orders` | GET |
| 상태변경 | `/api/v1/production/orders/{id}/status` | PATCH |

### 1.2 상태 전이

**업무 시나리오**: READY → RUNNING → DONE/ERROR

#### 상태 전이 규칙

```
READY ─[시작]→ RUNNING ─[일시정지]→ PAUSE ─[재시작]→ RUNNING
                  │                      │
                  └──────[완료]──────────┴──→ DONE
                  │
                  └──────[에러]──────────────→ ERROR ─[재시작]→ RUNNING
```

#### 상태별 액션

| 현재 상태 | 가능 액션 | 다음 상태 |
|---------|---------|---------|
| READY | 시작 | RUNNING |
| RUNNING | 일시정지, 완료, 에러 | PAUSE, DONE, ERROR |
| PAUSE | 재시작, 완료 | RUNNING, DONE |
| ERROR | 재시작 | RUNNING |
| DONE | 없음 | - |

#### 검증 포인트

**상태 전이 조건**
- [ ] READY → RUNNING: 설비 가용 상태 확인
- [ ] RUNNING → PAUSE: 사유 선택 (비가동 사유)
- [ ] RUNNING → DONE: 목표수량 달성 확인 (경고만)
- [ ] ERROR → RUNNING: 에러 원인 해결 확인

**시간 기록**
- [ ] 시작 시간: 상태 RUNNING 전환 시 자동 기록
- [ ] 종료 시간: 상태 DONE 전환 시 자동 기록

### 1.3 탭별 필터

**경로**: `/production/orders?view={tab}`

| 탭 | 필터 | 설명 |

## 2. 생산실적 (`/production/results`)

### 2.1 실적 등록

**사용자**: 오퍼레이터
**업무 흐름**: 작업 완료 → 양품/불량 카운트 → 실적 입력

#### 업무 시나리오

**2.1.1 실시간 실적 입력 (정상)**
```
작업 완료 → 양품/불량 카운트 → 실적 입력 → 다음 작업 또는 종료
```

1. **실적 데이터 입력**
   - 작업지시 선택
   - 양품 수량 (ok_qty)
   - 불량 수량 (ng_qty)
   - 작업자 ID
   - 공정/설비 자동 매핑

**2.1.2 불량 다발 시 실적 처리**
```
불량 발생 → 실적 입력 (ng_qty 높음) → 수율 경고 → NCR 연계
```

1. **불량 실적 등록**
   - 불량 수량 입력 시 수율 자동 계산
   - 수율 < 80%: 빨간색 경고 표시
   - 불량 유형별 원인 메모 기록

2. **NCR 연계**
   - 심각 불량 시 `/quality/ncr`에서 NCR 등록
   - 작업지시 ID 연결로 추적성 확보
   - 불량유형, 심각도, 근본원인 기록

**2.1.3 교대 근무 실적 인계**
```
1교대 종료 → 진행중 작업 실적 저장 → 2교대 시작 → 잔여 작업 계속
```

1. **교대 시 실적 마감**
   - 현재까지 양품/불량 수량 저장
   - 작업지시 상태: RUNNING 유지 (완료 아님)
   - end_time: 교대 시점으로 기록

2. **후속 교대 작업 시작**
   - 동일 작업지시 선택
   - start_time: 교대 시작 시점
   - 이전 실적과 별도 레코드로 저장

**2.1.4 목표수량 초과 생산**
```
목표 도달 → 추가 생산 필요 → 초과 실적 입력 → 경고 확인 후 저장
```

1. **초과 생산 처리**
   - 누적 실적 > 목표수량 시 경고 표시
   - 10% 초과까지 허용 (soft limit)
   - 초과 사유 비고에 기록 권장

#### 실적 데이터 구조

| 필드 | 설명 | 검증 |
|-----|------|------|
| work_order_id | 작업지시 FK | 존재하는 WO |
| process_routing_id | 공정 라우팅 | 해당 WO의 라우팅 |
| equipment_id | 사용 설비 | 존재하는 설비 |
| ok_qty | 양품 수량 | ≥ 0 |
| ng_qty | 불량 수량 | ≥ 0 |
| start_time | 시작 시간 | < end_time |
| end_time | 종료 시간 | > start_time |
| operator_id | 작업자 | 선택 |

#### 검증 포인트

**데이터 정합성**
- [ ] ok_qty + ng_qty > 0 (최소 1개 생산)
- [ ] start_time < end_time
- [ ] 누적 실적 ≤ 목표수량 × 1.1 (10% 초과 경고)
- [ ] equipment_id가 WO의 라우팅에 해당하는 설비

**수율 계산**
```
수율(%) = ok_qty / (ok_qty + ng_qty) × 100
```

**수율 배지 색상**
| 수율 | 색상 | 판정 |
|-----|------|------|
| ≥ 95% | 녹색 | 양호 |
| 80-95% | 노란색 | 주의 |
| < 80% | 빨간색 | 불량 |

## 3. 스케줄링 (`/scheduler`)

### 3.1 스케줄 현황 조회

**사용자**: 생산계획담당자, 현장관리자
**업무 흐름**: 스케줄 조회 → 설비별 작업 확인 → 진행상황 모니터링

**경로**: `/scheduler`

#### 업무 시나리오

**3.1.1 일일 스케줄 확인 (오전)**
```
08:30 출근 → 오늘 스케줄 조회 → 설비별 작업 할당 확인 → 현장 배포
```

1. **오늘 스케줄 확인**
   - `/scheduler` → 오늘 날짜 자동 선택
   - Gantt 차트에서 전체 현황 파악
   - 요약 카드: 가동 설비 수, 예정 작업 수

2. **설비별 작업 확인**
   - 각 설비 라인별 작업지시 순서 확인
   - 작업 블록 클릭 → 상세 정보 팝업
   - 예상 시작/종료 시간 확인

3. **현장 배포**
   - 설비별 작업 목록 인쇄 또는 화면 공유
   - 우선순위 높은 작업 강조

**3.1.2 실시간 진행 모니터링**
```
작업 중 → 실적 입력 반영 → 진행률 업데이트 → 지연 감지
```

1. **진행률 확인**
   - Gantt 블록 색상으로 상태 구분
   - RUNNING: 녹색, 진행중
   - PAUSE: 노란색, 일시정지
   - 예정 대비 지연 작업 확인

2. **지연 대응**
   - 지연 작업 식별 → 원인 파악
   - 필요 시 스케줄 재조정 검토

**3.1.3 주간/월간 계획 조회**
```
계획 수립 → 기간 설정 → 부하 분석 → 용량 검토
```

1. **기간별 조회**
   - 날짜 선택기로 기간 변경
   - 주간 단위: 요일별 부하 확인
   - 월간 단위: 설비 가동률 추세

#### Gantt 차트
- X축: 시간 (horizonStart ~ horizonEnd)
- Y축: 설비 (resources)
- 블록: 작업지시 (tasks)
- 색상: 상태별 구분

#### UI 요소
- 날짜 선택 (date picker)
- 오늘 버튼
- 요약 카드 (스케줄된 설비, 예정 작업지시, 진행중)

### 3.2 스케줄 실행

**사용자**: 생산계획담당자
**업무 흐름**: 파라미터 설정 → 솔버 실행 → 결과 검토 → 승인/반려

**경로**: `/scheduler/execute`

#### 업무 시나리오

**3.2.1 일일 스케줄 생성 (정규)**
```
09:00 작업지시 확정 → 스케줄 실행 → 결과 검토 → 승인 → 현장 배포
```

1. **파라미터 설정**
   - horizon_hours: 24 (1일)
   - time_limit_sec: 60 (1분)
   - solver: OR-Tools (기본)
   - include_running: false (신규만)

2. **솔버 실행**
   - "스케줄 실행" 버튼 클릭
   - 상태: idle → solving → review
   - 진행 표시기 확인

3. **결과 검토**
   - Makespan 확인 (총 소요시간)
   - 설비 가동률 확인
   - 미배정 작업 유무 확인
   - 납기 준수 여부 확인

4. **승인**
   - "승인" 버튼 → 작업지시 plan_start/plan_end 업데이트
   - 상태: review → approved

**3.2.2 긴급 스케줄 재조정**
```
긴급 오더 추가 → 기존 스케줄 취소 → 재스케줄 실행 → 변경 검토 → 승인
```

1. **재스케줄 실행**
   - include_running: true (진행중 작업 포함)
   - 긴급 오더 우선순위 반영
   - 기존 RUNNING 작업 중단 최소화

2. **변경 영향 분석**
   - 기존 대비 변경된 작업 확인
   - 납기 지연 예상 작업 식별
   - 고객 통보 필요 여부 판단

**3.2.3 대규모 스케줄 (주간)**
```
주간 계획 수립 → horizon 168h → GA/SA 솔버 → 장시간 실행 → 결과 검토
```

1. **대규모 파라미터**
   - horizon_hours: 168 (1주)
   - time_limit_sec: 300 (5분)
   - solver: GA 또는 SA (근사해 빠름)

2. **장시간 실행 대응**
   - 백그라운드 실행
   - 완료 시 알림
   - 중간 취소 가능

**3.2.4 스케줄 실패 대응**
```
솔버 실패 → 에러 원인 확인 → 제약조건 완화 → 재시도
```

1. **실패 원인 파악**
   - 설비 가용성 부족
   - 시간 제한 초과 (time_limit)
   - 제약조건 충돌 (선후행 불가)

2. **재시도**
   - time_limit 증가
   - horizon 축소
   - 일부 작업 제외 후 재실행

#### 솔버 옵션

| 솔버 | 특징 | 권장 상황 |
|-----|------|---------|
| OR-Tools (CP-SAT) | 최적해, 정확 | 중소규모, 정밀 스케줄 |
| GA (유전 알고리즘) | 근사해, 빠름 | 대규모, 복잡 제약 |
| SA (담금질) | 근사해, 안정적 | 중간 규모 |
| TABU (타부 서치) | 근사해, 탐색적 | 지역 최적 탈출 필요 시 |

#### 실행 파라미터

| 파라미터 | 범위 | 기본값 | 설명 |
|---------|------|-------|------|
| horizon_hours | 1-168 | 24 | 계획 기간 (시간) |
| time_limit_sec | 10-300 | 60 | 솔버 제한 시간 (초) |
| include_running | bool | false | 진행중 작업 포함 |

#### 워크플로우 상태

```
idle → solving → review → approving → approved
         │         │
         │         └─[취소]→ idle
         └─[실패]→ idle + 에러 표시
```

#### 검증 포인트

**스케줄 결과 검증**
- [ ] 같은 설비에서 시간 겹침 없음
- [ ] 선후행 공정 순서 준수
- [ ] plan_start < plan_end
- [ ] 모든 READY 작업 배정 (또는 미배정 사유)

**데이터 정합성**
- [ ] Makespan = max(plan_end) - min(plan_start)
- [ ] 가동률 = Σ(작업시간) / (설비수 × horizon)
- [ ] 스케줄 결과 → 작업지시 plan_start/plan_end 업데이트

### 4.3 NCR 관리

**사용자**: 품질관리담당자, 생산관리자
**업무 흐름**: NCR 등록 → 원인 분석 → 시정조치 → 예방조치 → 종결

**경로**: `/quality/ncr`

#### 업무 시나리오

**4.3.1 NCR 등록 (불합격 발생 시)**
```
불합격 발생 → NCR 생성 → 불량유형/심각도 분류 → 담당자 배정 → 조치 요청
```

1. **NCR 생성**
   - 검사결과 또는 생산실적에서 연계
   - 불량유형 선택 (치수/표면/재료/공정)
   - 심각도 판정 (CRITICAL/MAJOR/MINOR)

2. **담당자 배정**
   - 불량 유형에 따라 담당 부서 지정
   - 처리 기한 자동 설정 (심각도 기준)
   - 조치 요청 알림

**4.3.2 NCR 처리 (시정조치)**
```
NCR 접수 → 근본원인 분석 → 시정조치 수행 → 효과 확인 → 종결 요청
```

1. **원인 분석**
   - 5 Why 분석 또는 특성요인도 활용
   - 근본원인(root_cause) 기록
   - 재발방지 대책 수립

2. **시정조치 수행**
   - 시정조치(corrective_action) 기록
   - 조치 완료일 입력
   - 증빙자료 첨부 (선택)

3. **효과 확인**
   - 동일 불량 재발 모니터링
   - 효과 검증 후 종결 요청

**4.3.3 NCR 검증 (품질팀)**
```
종결 요청 접수 → 조치 내용 검토 → 효과 검증 → 승인/반려
```

1. **검토 및 검증**
   - 시정조치 적절성 확인
   - 예방조치 수립 여부 확인
   - 유사 불량 발생 현황 확인

2. **승인/반려**
   - 승인: VERIFIED 상태로 전환
   - 반려: 보완 요청 후 IN_PROGRESS로 복귀

**4.3.4 NCR 현황 모니터링**
```
주간 회의 → NCR 현황 조회 → 불량 추세 분석 → 개선 과제 도출
```

1. **현황 대시보드**
   - 상태별 NCR 건수 조회
   - 불량유형별 파레토 분석
   - 미처리 NCR 목록 확인

2. **추세 분석**
   - 월별 NCR 발생 추이
   - 심각도별 분포
   - 주요 원인 패턴

#### NCR 상태 전이

```
OPEN ─[진행시작]→ IN_PROGRESS ─[완료]→ CLOSED ─[검증완료]→ VERIFIED
```

#### NCR 데이터 구조

| 필드 | 설명 | 필수 |

### 4.4 SPC

**사용자**: 품질엔지니어, 공정엔지니어
**업무 흐름**: 관리도 모니터링 → 이상 감지 → 원인 분석 → 공정 조정

**경로**: `/quality/spc`

#### 업무 시나리오

**4.4.1 실시간 공정 모니터링**
```
생산 중 → 측정값 입력 → 관리도 업데이트 → 관리한계 이탈 감지 → 즉시 대응
```

1. **관리도 확인**
   - 제품/검사항목 선택
   - X-bar, R 차트 동시 확인
   - UCL/LCL 기준선 표시

2. **이상 감지 (OOC)**
   - 관리한계 이탈 점 빨간색 강조
   - 연속 7점 상승/하강 트렌드 경고
   - 중심선 기준 연속 편향 경고

3. **즉시 대응**
   - 공정 일시 중단
   - 원인 조사 (설비, 원자재, 작업자)
   - 조정 후 재가동

**4.4.2 공정능력 분석**
```
안정 상태 확인 → 데이터 수집 → Cp/Cpk 계산 → 개선 필요성 판단
```

1. **안정성 확인**
   - 관리도상 이상 패턴 없음 확인
   - 최소 25개 서브그룹 데이터 확보

2. **공정능력지수 확인**
   - Cp ≥ 1.33: 공정 능력 양호
   - 1.0 ≤ Cp < 1.33: 개선 권장
   - Cp < 1.0: 개선 필수

3. **Cpk 해석**
   - Cpk ≈ Cp: 공정 중심 양호
   - Cpk << Cp: 공정 중심 이동 필요

**4.4.3 공정 개선 후 재평가**
```
공정 변경 → 시험 생산 → 재측정 → 관리한계 재설정 → Cpk 재계산
```

1. **관리한계 재설정**
   - 기존 데이터 리셋
   - 신규 데이터로 UCL/LCL 재계산
   - 개선 효과 비교

2. **개선 효과 검증**
   - 산포 감소 확인 (R-bar 감소)
   - 평균 이동 확인 (Target 근접)
   - Cpk 개선 확인

#### 관리도 (Control Chart)

| 관리도 | 용도 | 관리 한계 |
|-------|------|----------|
| X-bar | 평균 관리 | UCL/LCL = X̄ ± A₂R̄ |
| R | 범위 관리 | UCL = D₄R̄, LCL = D₃R̄ |

#### 공정능력지수

| 지수 | 공식 | 기준 |
|-----|------|------|
| Cp | (USL - LSL) / 6σ | ≥ 1.33 양호 |
| Cpk | min(Cpu, Cpl) | ≥ 1.33 양호 |

#### 검증 포인트
- [ ] 관리한계 자동 계산
- [ ] OOC (Out of Control) 점 강조
- [ ] Cp/Cpk 실시간 표시


1. **월간 집계**
   - 월간 OEE 평균/추이
   - 월간 생산량/불량률
   - 비가동 시간 분석

2. **비교 분석**
   - 전월 대비 개선/악화 항목
   - 전년 동월 대비 추이
   - 연간 목표 대비 진도율

**경로**: `/analytics`

#### KPI 카드
- 전체 OEE
- 가용성 (Availability)
- 성능 (Performance)
- 품질 (Quality)

#### OEE 계산

```
OEE = 가용성(A) × 성능(P) × 품질(Q)
```

| 지표 | 공식 | 목표 |
|-----|------|------|
| 가용성 (A) | 가동시간 / 계획가동시간 | ≥ 90% |
| 성능 (P) | (생산량 × 표준CT) / 가동시간 | ≥ 95% |
| 품질 (Q) | 양품수량 / 생산수량 | ≥ 99% |
| OEE | A × P × Q | ≥ 85% |

### 6.2 Lot 추적

**사용자**: 품질관리담당자, 생산관리자
**업무 흐름**: Lot 조회 → 전체 이력 확인 → 품질 문제 원인 추적

**경로**: `/analytics/lot-trace`

#### 업무 시나리오

**6.2.1 고객 클레임 대응 (역추적)**
```
고객 클레임 접수 → Lot No 확인 → 생산 이력 조회 → 원인 추적 → 회신
```

1. **Lot 정보 조회**
   - 고객 제공 Lot No 입력
   - 생산일, 작업지시, 수량 확인
   - 사용 설비, 작업자 확인

2. **품질 이력 확인**
   - 각 공정별 검사 결과 확인
   - 측정값 및 합격/불합격 이력
   - 동일 Lot 내 불량 발생 여부

3. **원인 분석**
   - 불량 발생 공정 특정
   - 해당 시점 설비 상태 확인
   - 동시간대 다른 Lot 영향 확인

4. **대응**
   - 원인 분석 결과 정리
   - 시정조치 계획 수립
   - 고객 회신

**6.2.2 선행 추적 (영향 범위 파악)**
```
원자재 불량 발견 → 사용 Lot 조회 → 영향 Lot 식별 → 리콜 범위 결정
```

1. **원자재 사용 이력 조회**
   - 불량 원자재 Lot No 입력
   - 해당 원자재 사용 작업지시 조회
   - 영향받은 완제품 Lot 목록

2. **리콜 범위 결정**
   - 출하 여부 확인
   - 출하된 고객/수량 확인
   - 리콜 또는 현장 재고 격리

**6.2.3 공정별 이력 분석**
```
불량 패턴 발견 → 해당 공정 이력 조회 → 공통 요인 분석 → 개선
```

1. **공정 이력 조회**
   - 특정 공정에서 불량 집중 시
   - 해당 공정 Lot별 이력 조회
   - 설비, 작업자, 파라미터 비교

2. **공통 요인 분석**
   - 특정 설비에서 불량 집중
   - 특정 작업자 패턴
   - 특정 시간대/교대 패턴

**경로**: `/analytics/lot-trace`

#### 추적 정보

| 항목 | 내용 |
|-----|------|
| 생산 이력 | 각 공정별 시작/종료, 양품/불량, 작업자, 설비 |
| 품질 이력 | 검사 항목별 측정값, 합격/불합격 |
| 설비 이력 | 사용 설비, 가공 파라미터 |

#### 검증 포인트
- [ ] Lot No 검색 시 전체 이력 조회
- [ ] 공정 순서대로 타임라인 표시
- [ ] 불량 발생 공정 강조 표시
- [ ] 연관 NCR 연결

# Part 2: End-to-End 통합 시나리오

## E2E-1. 신규 수주 → 출하 전체 흐름

```
수주 접수 → 작업지시 생성 → 스케줄 실행 → 생산 시작 → 실적 입력 → 
품질검사 → 완료 처리 → 출하 판정
```

### 단계별 흐름

| 단계 | 담당 | 화면 | 주요 액션 |
|-----|------|------|---------|
| 1. 작업지시 생성 | 생산계획 | `/production/orders` | 신규 WO 등록 |
| 2. 스케줄 실행 | 생산계획 | `/scheduler/execute` | 솔버 실행 → 승인 |
| 3. 작업 시작 | 현장 | `/production/orders` | READY → RUNNING |
| 4. 실적 입력 | 오퍼레이터 | `/production/results` | 양품/불량 입력 |
| 5. 공정검사 | 품질검사원 | `/quality/inspection-results` | 측정값 입력 |
| 6. 작업 완료 | 현장 | `/production/orders` | RUNNING → DONE |
| 7. 최종검사 | 품질검사원 | `/quality/inspection-results` | 합격 판정 |
| 8. 출하 | 물류 | (외부 시스템) | 출하 처리 |

### 분기 시나리오

**불합격 발생 시:**
```
공정검사 불합격 → NCR 등록 → 재작업 or 폐기 → 재검사 → 합격 시 진행
```

**설비 고장 시:**
```
설비 BREAKDOWN → 작업 PAUSE → 대체 설비 배정 → 스케줄 재조정 → 작업 재개
```
