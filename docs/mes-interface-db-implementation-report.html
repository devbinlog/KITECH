MES to APS Interface

MES Interface DB 구현 보고서

SQLite 기반 MES 데이터를 PostgreSQL Interface DB로 복제하고, APS에는 읽기 전용 View 계약으로 제공하는 구조

작성일: 2026-09-04 · 대상: MES 개발팀, APS 연동팀, 운영 담당자

구현 배경

회의에서 나온 요구

  • MES 데이터를 APS에서 읽을 수 있게 제공한다.
  • MES DB를 직접 열어주는 방식은 피한다.
  • 작업지시, 라우팅, 설비, 실적, 다운타임 데이터를 우선 제공한다.
  • APS 결과 쓰기는 스키마가 확정된 뒤 후속 단계로 둔다.

기술적 제약

  • 현재 MES 원천 DB는 SQLite 파일이다.
  • SQLite는 외부 네트워크 접속용 서버 DB가 아니다.
  • MES는 계속 개발 중이라 스키마 변경 가능성이 높다.
  • 외부 업체에는 최소 권한 계정만 제공해야 한다.
결론: SQLite를 직접 공개하지 않고 PostgreSQL Interface DB를 별도로 둔다.

Docker Compose 구성

서비스 역할 주요 설정
mes-interface-db PostgreSQL Interface DB 15433:5432, DB mes_interface
mes-interface-sync SQLite 데이터를 PostgreSQL로 복사 MES data volume read-only mount, 매일 02:00/14:00 실행
mes_interface_db_data는 컨테이너가 아니라 Docker volume이다. PostgreSQL 데이터 파일을 저장하며 docker volume ls에서 확인한다.
docker compose up -d mes-interface-db mes-interface-sync
docker compose run --rm mes-interface-sync sync-once

Interface DB 스키마

mes_src

원본 미러링

MES 테이블을 원본에 가깝게 복사한다. APS가 직접 조회하지 않는다.

mes_if

APS 조회 View

외부 연동 계약 영역이다. APS는 이 스키마만 읽는다.

if_admin

운영 로그

배치 성공, 실패, 스키마 스냅샷, 테이블별 row count를 기록한다.

aps_if는 APS 결과 쓰기 영역으로 예약했으며 1차 범위에서는 쓰기 권한을 열지 않았다.

동기화 방식

1차 전략

  • 하루 2회 전체 refresh를 수행한다.
  • 운영 중 SQLite를 직접 오래 읽지 않고 backup API로 스냅샷을 만든다.
  • 스냅샷 기준으로 PostgreSQL mes_src를 재적재한다.
  • 동기화 결과는 if_admin.sync_batches에 남긴다.

현재 검증 상태

  • SUCCESS 최신 배치 확인
  • 27개 MES 테이블 복사
  • 2,747 row 적재
  • APS 계정으로 if_work_orders 조회 성공

View 매핑 YAML

핵심 APS View는 agents/mes-interface-sync/config/interface_views.yaml에서 관리한다.

views:
  - name: if_work_orders
    source_table: work_orders
    columns:
      - name: qty
        source_candidates:
          - qty
          - target_qty
        required: true
      - name: due_date
        source_candidates:
          - due_date
          - delivery_date
          - deadline_at
        required: false
MES 컬럼명이 바뀌면 후보 컬럼을 YAML에 추가해서 APS 컬럼명을 유지한다.

접속과 보안

APS 제공 정보

  • Host: 공장 PC 또는 서버 IP
  • Port: 15433
  • Database: mes_interface
  • User: aps_user
  • Schema: mes_if

노출 제한

  • APS 계정은 read-only이다.
  • users, middleware_config, alembic_version은 제외한다.
  • 설비 접속 설정, 파일 경로, raw metadata는 View에서 제외한다.
  • 비밀번호는 문서가 아니라 별도 보안 채널로 전달한다.

운영 확인 쿼리

select status, table_count, row_count, started_at, completed_at, error_message
from if_admin.sync_batches
order by started_at desc
limit 3;

select table_name
from information_schema.views
where table_schema = 'mes_if'
order by table_name;

select *
from mes_if.if_work_orders
order by due_date nulls last, priority desc, id
limit 100;
외부 APS 업체에는 APS_ACCESS_GUIDE.md를 기준 문서로 전달한다.

후속 결정 사항

운영 전 확인

  • APS 업체에 전달할 실제 Host IP 확정
  • 공유기 또는 방화벽에서 외부 포트포워딩 설정
  • 비밀번호 전달 채널 확정
  • 파일럿 후 계정 비밀번호 회전

후속 개발

  • APS 결과 쓰기 스키마 확정 후 aps_if 개방
  • 필요 시 source IP 제한 또는 VPN 적용
  • 데이터량 증가 시 증분 동기화 검토
  • 스키마 변경 알림 채널 추가
