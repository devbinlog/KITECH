## 1. 개요
현재 `localhost:8000`에서 동작 중인 미들웨어와 통신하기 위해 `Cell-MES`와 `NL-Router` 에이전트 간의 연결을 구축하고, 통합 테스트(`test_nlrouter_mes_integration.py`)를 통과시키기 위한 전체 환경 디버깅 및 QA 과정을 기록합니다.

## 2. 발생한 주요 이슈 및 트러블슈팅 로그

### 2.1. 포트 충돌 및 API 환경 변수 설정 이슈 (404 Not Found)
* **문제 증상**: 기존 미들웨어가 8000 포트를 점유하고 있어 `Cell-MES`가 부팅되지 않거나 통신이 엇갈림.
* **조치 과정**:
  * `services.env` 및 `.env.dev`의 `Cell-MES` 구동 포트를 `8080` 포트로 변경.
  * `NL-Router`에서 `Cell-MES`를 바라보는 API 주소 중, Pydantic `@property`로 정의된 `MES_API_BASE_URL` 환경변수가 무시되고 기본값인 8000 포트로 폴백되어 계속해서 `404 Not Found` 에러(미들웨어 서버로 잘못된 요청)를 발생시키는 것을 발견.
  * `NL-Router`의 `.env` 파일 내부에서 `MES_API_BASE_URL`을 `CELL_MES_URL=http://localhost:8080`으로 직접 명시하여 수정 적용.

### 2.2. 내부 서비스 호출 인증 실패 이슈 (401 Unauthorized)
* **문제 증상**: 포트 에러 해결 후 API 호출 시 `401 Unauthorized` 권한 없음 에러 발생.
* **조치 과정**:
  * `NL-Router`가 `Cell-MES` 시스템의 API(예: `/api/v1/masters/equipments`)에 접근할 때 사내 서비스 호출용 인증 헤더가 필요함 파악.
  * 통합 테스트 환경 코드(`tests/integration/test_nlrouter_mes_integration.py`) 내의 POST 요청 헤더에 `X-Internal-Service-Key`를 하드코딩 혹은 환경변수로부터 주입하도록 패치 완료.

### 2.3. SQLite 데이터베이스 마이그레이션 스키마 오류 (500 Internal Server Error)
* **문제 증상**: 인증 해결 후 `/api/v1/equipments?status=ERROR` 등의 특정 장비 조회 조회 API를 호출하면 `500 Server Error` (sqlite3.OperationalError: no such column: equipments.eq_code 등)가 반환.
* **조치 과정**:
  * FastAPI 백엔드 프로세스의 에러 트레이스백을 위해 로깅 파이프라인 우회(`err.txt`) 및 curl 테스트. 파악 결과, SQLAlchemy 정의(Equipment) 상에는 `eq_code` 컬럼 등이 존재하지만, 실제 SQLite DB 파일 속 테이블엔 컬럼이 마이그레이션되지 않았음 발견.
  * `alembic upgrade head` 명령어 시도시 이미 추가된 컬럼이라는 중복 오류 발생 (`004` 마이그레이션 버전의 버그). 
  * 분석 결과 **Alembic `004` 마이그레이션 스크립트에 이전에 `002` 마이그레이션에 이미 적용되었던 `equipment_type`, `cycle_time_sec` 컬럼 추가 구문이 중복 작성**되어 있어 충돌이 일어나는 점을 발견.
  * **해결 방안 실행**:
    1. PowerShell 상의 Background `uvicorn` 프로세스들이 `.db` 파일을 락(Lock)걸고 있어 초기화가 불가하여, 관련 Python 백그라운드 프로세스를 모두 강제종료.
    2. 데이터가 엉킨 SQLite 파일(`agents/cell-mes/data/mes.db`) 강제 완전 삭제.
    3. Alembic `004_add_process_categories_and_cells.py` 스크립트 수정하여 중복 컬럼 및 인덱스 구문 제거 (`equipment_type`, `cycle_time_sec`).
    4. 새로운 SQLite 데이터베이스에 깔끔하게 `uv run alembic upgrade head` 실행하여 오류 없이 스키마 복구 달성.

## 4. 추가 작업 내용 (2026-03-04) - 미들웨어 통합 연동 완료

외부 PC에서 구동 중인 실제 미들웨어(`10.10.10.126:8000`)와의 실시간 통합 연동을 완료하였습니다.

### 4.1. 외부 미들웨어 연결 및 헬스 체크 안정화
- **연결 설정**: 모든 시스템의 `MIDDLEWARE_URL`을 외부 IP `http://10.10.10.126:8000`으로 일원화.
- **상태 모니터링**: 422 에러를 발생시키던 `/debug/status` 대신 `/api/aas/view`를 사용하도록 수정하여 UI에서 실시간 연결 상태("연결됨")가 정상 표시되도록 개선.

### 4.2. 실시간 자동 데이터 수집 (Background Polling)
- **자동 폴링 도입**: `cell-mes` 백엔드에 asyncio 기반 백그라운드 태스크를 구현하여 **3초마다** 자동으로 미들웨어 데이터를 수집하도록 처리. 
- **데이터 성능 최적화**: 개별 장비별 조회가 아닌 `/api/aas/view` 벌크 조회를 활용하여 네트워크 부하를 줄이고 데이터 동시성을 확보하도록 `polling_service.py` 전면 개편.

### 4.3. 로봇 가동 상태 및 AAS 동기화 로직 고도화
- **상태 매핑 교정**: 로봇의 `BUSY`, `WORKING`, `ACTIVE` 등의 상태값이 MES UI에서 '정지'로 표시되던 문제를 해결하기 위해 **가동중(RUN)** 상태 매핑 로직 추가.
- **확인 절차 추가**: AAS 장비 동기화 시, 기존 시드 데이터(잘못된 ID)를 삭제할지 사용자가 선택할 수 있도록 **삭제 확인 다이얼로그** 및 API 옵션(`delete_orphans`) 구현.

### 4.4. 데이터베이스 AAS ID 무결성 고도화
- **ID 불일치 해결**: 기존 시드 데이터의 장비 ID(`aas:cnc:...`)가 실제 미들웨어 URI(`https://...`)와 달라 폴링 매칭이 안 되던 문제를 해결하기 위해, DB의 설비 테이블을 실제 미들웨어 ID 체계로 일괄 업데이트.
- **결과**: CNC 도어 상태(`door_state`), 로봇 가동 상태 등이 UI에 실시간 수량화되어 표시됨을 확인 완료.

## 5. 추가 작업 내용 (2026-03-05) - 생산 API 아키텍처 개선 및 기능 확장

### 5.1. 로트 생성/시작 분리 아키텍처 전환
- **작업지시 생성 시점**: `POST /orders` 호출 → 즉시 미들웨어 로트 생성(`POST /api/lots`) 및 NC 파일 배열 전송
- **작업지시 시작 시점**: `POST /orders/{id}/start` 호출 → 로트 시작 신호(`POST /api/lots/{lot_no}/start`) 만 하달
- **프론트엔드**: 작업 시작 다이얼로그에서 파일 업로드 폼 제거, 안내 메시지만 표시

### 5.2. 작업지시 삭제 기능 신설 (미들웨어 로트 연동)
- 백엔드: `DELETE /api/v1/production/orders/{id}` 엔드포인트 신설
- 미들웨어의 `DELETE /api/lots/{lot_no}` 선행 호출 후 MES DB 삭제 처리
- RUNNING 상태 삭제 불가, 거절 시 미들웨어 사유 메시지 프론트엔드로 전달
- 프론트엔드: 상태별 🗑️ 삭제 버튼 및 확인 모달 추가

### 5.3. LOT 중지/재시작 미들웨어 연동
- `RUNNING → PAUSE/DONE/CANCEL`: 미들웨어 `POST /api/lots/{lot_no}/stop` 자동 호출
- `PAUSE → RUNNING`: 미들웨어 `POST /api/lots/{lot_no}/resume` 자동 호출

### 5.4. NC 파일 파일 선택기 개선
- 확장자 없는 NC 파일(O0002 등)도 선택 가능하도록 브라우저 `accept` 속성 제거 처리
- 프론트엔드 API 호출 경로 오탈자(`/master` → `/masters`) 수정

### 5.5. 시나리오 수정 기능 누락 버그 수정
- `ScenarioUpdate` 스키마 추가 (`master.py`)
- `PATCH /api/v1/masters/scenarios/{id}` 수정 엔드포인트 신설 (`scenarios.py`)
