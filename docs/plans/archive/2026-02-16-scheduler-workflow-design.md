# 스케줄링 수립자 워크플로우 설계

**작성일**: 2026-02-16
**상태**: 설계 완료
**대상 역할**: 스케줄링 수립자 (Production Planner)
**범위**: 스케줄러 3개 화면 + 작업지시 연계

## 1. 화면 구성

| 화면 | 경로 | 주요 기능 |
|------|------|----------|
| 스케줄 현황 | `/scheduler` | 일별 간트차트, 설비별 스케줄 조회 |
| 스케줄 실행 | `/scheduler/execute` | 솔버 실행 → 결과 검토 → 승인 |
| 솔버 설정 | `/scheduler/settings` | 기본 파라미터, 솔버 타입 설정 |
| 작업지시 목록 | `/production/orders` | 스케줄 반영 확인 |

## 2. 스케줄링 모드 정의

스케줄러는 3개 플래그 조합으로 **3가지 운영 모드**를 제공합니다.

### 2.1 플래그 설명

| 플래그 | 기본값 | 역할 |
|--------|--------|------|
| `include_running` | `false` | 진행중(RUNNING) 작업지시를 스케줄 대상에 포함 |
| `include_scheduled` | `false` | 이미 스케줄된 작업지시를 다시 포함 (드리프트 방지용) |
| `horizon_hours` | `24` | 현재 시점부터 몇 시간 앞까지 계획 (1~168시간) |

### 2.2 운영 모드

| 모드 | include_running | include_scheduled | 대상 작업지시 | 사용 시나리오 |
|------|----------------|-------------------|-------------|-------------|
| **A. 신규 수립** | `false` | `false` | READY만 | 매일 아침 당일 스케줄 생성 |
| **B. 재스케줄링** | `false` | `true` | READY + 기스케줄 | 우선순위 변경, 납기 변경 시 기존 스케줄 재배치 |
| **C. 전체 재배치** | `true` | `true` | READY + 기스케줄 + RUNNING | 긴급 장비 고장, 대규모 계획 변경 시 진행중 포함 재배치 |

### 2.3 모드별 영향 범위

```
모드 A (신규):     [READY] → 솔버 → 스케줄 결과 → 승인 → WO 업데이트
                   기존 스케줄/진행중 작업 영향 없음

모드 B (재스케줄):  [READY + 기스케줄] → 솔버 → 스케줄 결과 → 승인 → WO 업데이트
                   기존 스케줄이 새 결과로 덮어씌워짐
                   진행중 작업 영향 없음

모드 C (전체):     [READY + 기스케줄 + RUNNING] → 솔버 → 스케줄 결과 → 승인 → WO 업데이트
                   모든 작업이 재배치됨 (주의 필요)
```

## 3. 워크플로우 시나리오

### 시나리오 1: 일일 스케줄 확인

**업무**: 출근 후 당일 스케줄 현황 파악

**단계**:
1. `/scheduler` 진입
2. 당일 날짜 기본 선택 확인
3. 요약 카드 3개 확인: 스케줄된 설비/작업/진행중 수
4. 간트차트에서 설비별 타임라인 확인
   - 상태 색상: READY(파랑), RUNNING(초록), DONE(회색), PAUSE(노랑), ERROR(빨강)
   - 블록 호버: WO ID, Lot No, 제품명, 시작/종료, 수량
   - 블록 클릭: 해당 작업지시 페이지 이동
5. 날짜 변경으로 다른 날 조회 / "오늘" 버튼으로 복귀

**API**: `GET /api/v1/scheduler/current-schedule?date=YYYY-MM-DD`

---

### 시나리오 2A: 신규 스케줄 수립 (모드 A)

**업무**: 매일 아침 READY 작업지시를 대상으로 당일 스케줄 생성

**전제**: READY 작업지시 1건+, 가용 설비 1대+ 존재

**단계**:

#### Phase 1: 대기 (idle)
1. `/scheduler/execute` 진입, 상태 뱃지 "대기"
2. 가용 설비 카드 확인 (설비 수, JSON 보기)
3. 스케줄 대상 카드 확인 (READY 작업지시 수, JSON 보기)
4. 설비 목록 테이블: Machine ID, 이름, 타입, 상태, 가용 시간
5. 작업지시 목록 테이블: WO ID, Lot No, 제품, 수량, 우선순위, 납기일

#### Phase 2: 파라미터 설정 & 실행
6. 계획 기간: 24시간 (당일)
7. 솔버 선택: OR_TOOLS (소규모) 또는 GA (대규모)
8. 시간 제한: 60초
9. "진행중 포함" 체크 해제 (기본)
10. "스케줄 실행" 클릭

#### Phase 3: 실행 중 (solving)
11. 상태 뱃지 "실행중", 스피너 표시

#### Phase 4: 결과 검토 (review)
12. 상태 뱃지 "검토중"
13. 결과 통계: Makespan, 평균 가동률, 스케줄 작업 수, 실행 시간
14. 스케줄 작업 테이블: WO ID, 공정, 설비, 시작/종료, 수량
15. 액션: 취소 / 다시 실행 / 스케줄 승인

#### Phase 5: 승인 (approved)
16. "스케줄 승인" 클릭
17. 상태 뱃지 "승인완료"
18. 업데이트된 작업지시 테이블: ID, Lot No, 계획 시작/종료, 할당 설비
19. "작업지시 목록 보기" 또는 "새 스케줄 생성"

**API 호출 순서**:
1. `GET /api/v1/scheduler/equipment-availability`
2. `GET /api/v1/scheduler/work-orders?status=READY`
3. `POST /api/v1/scheduler/solve` (`include_scheduled=false`, `include_running=false`, `auto_apply=false`)
4. `POST /api/v1/scheduler/process-result` (승인 시)

---

### 시나리오 2B: 재스케줄링 (모드 B)

**업무**: 우선순위/납기 변경으로 기존 스케줄을 재수립

**전제**: 기존 스케줄이 존재하고, 변경 사유 발생

**차이점** (시나리오 2A 대비):
- Phase 2에서 "진행중 포함" 체크 해제 상태
- **핵심**: 프론트엔드 UI에는 `include_scheduled` 체크박스가 현재 없음
  - API 레벨에서는 `include_scheduled=true`로 호출 가능
  - UI 보강 필요 여부 확인 포인트

**영향**: READY + 이미 스케줄된 작업지시가 모두 재배치됨
**주의**: 기존에 승인된 스케줄이 새 결과로 덮어씌워짐

**API**: `POST /api/v1/scheduler/solve` (`include_scheduled=true`, `include_running=false`)

---

### 시나리오 2C: 전체 재배치 (모드 C)

**업무**: 긴급 장비 고장 등으로 진행중 작업 포함 전체 재배치

**전제**: 긴급 상황 (설비 고장, 긴급 주문 등)

**차이점** (시나리오 2A 대비):
- Phase 2에서 "진행중 포함" 체크
- `include_scheduled=true` (API 레벨)
- 모든 작업지시(READY + 기스케줄 + RUNNING)가 대상

**영향**: 진행중 작업까지 재배치 → 현장 작업자에게 알림 필요
**주의**: 가장 파괴적 모드, 신중한 검토 필요

**API**: `POST /api/v1/scheduler/solve` (`include_scheduled=true`, `include_running=true`)

---

### 시나리오 3: 승인 후 작업지시 반영 확인

**업무**: 스케줄 승인 후 작업지시에 올바르게 반영되었는지 확인

**전제**: 시나리오 2A/2B/2C 중 하나 완료

**단계**:
1. 승인 완료 화면에서 "작업지시 목록 보기" 클릭
2. `/production/orders` 이동
3. 스케줄된 작업지시 확인:
   - 계획 시작/종료 시간 설정됨
   - 할당 설비 지정됨
4. 개별 작업지시 상세에서 scheduled_start, scheduled_end, assigned_equipment 확인

**검증 포인트**:
- 승인 결과의 updated_orders와 작업지시 목록 일치
- 시간이 합리적 (현재~미래)
- 할당 설비가 실제 존재
- 작업지시 상태 적절

---

### 시나리오 4: 솔버 설정 변경

**업무**: 기본 설정을 변경하고 다른 솔버 실험

**단계**:
1. `/scheduler/settings` 진입
2. 현재 설정 확인
3. 솔버 카드 클릭으로 타입 변경 (5종)
4. 계획 기간, 시간 제한 조정
5. 변경 감지: 우하단 노란 배너, 파라미터 테이블 하이라이트
6. "저장" 클릭 (localStorage)
7. `/scheduler/execute`로 이동, 변경된 기본값 반영 확인

**검증 포인트**:
- 설정이 localStorage에 저장/유지
- "초기화"로 기본값 복원 가능
- 실행 페이지에서 저장된 값이 기본 선택됨

---

### 시나리오 5: 결과 취소/재실행

**업무**: 결과 불만족 시 취소하거나 다른 설정으로 재실행

**경로 A - 취소**:
1. 검토 화면에서 "취소" 클릭
2. 상태 "대기"(idle) 복귀
3. 이전 결과 초기화, 설비/작업지시 목록 재표시

**경로 B - 재실행**:
1. "다시 실행" 클릭
2. 파라미터 변경 (다른 솔버, 시간 제한 등)
3. 새 결과 생성, 비교 후 결정

**검증 포인트**:
- 취소 시 작업지시 미변경
- 재실행 시 이전 결과 덮어씌움
- 반복 실행/취소 가능

---

### 시나리오 6: 데이터 정합성

**업무**: 스케줄 결과의 데이터 무결성 검증

#### A. 스케줄 내부 정합성
- 같은 설비 시간 중복 없음
- makespan > 0
- start_time < end_time
- 수량 > 0

#### B. 스케줄↔작업지시
- 스케줄된 WO ID가 실제 작업지시에 존재
- 승인 후 scheduled_start/end가 결과와 일치
- 할당 설비가 설비 마스터에 존재

#### C. 스케줄↔설비
- 사용된 설비가 equipment-availability에 존재
- 가용 시간 내 배치

#### D. 현황↔API
- 간트차트 작업 수 = API 응답 작업 수
- 날짜 변경 시 해당 날짜 데이터만 표시

## 4. 멀티솔버 비교 기능 (신규)

### 4.1 현재 문제

현재 워크플로우는 솔버 1개 실행 → 결과 1개 검토 → 승인/취소만 가능.
스케줄링 수립자가 **최적안을 선택하려면**:
- 여러 솔버 결과를 비교해야 함
- 기존 스케줄과도 비교해야 함
- 각 결과의 KPI(Makespan, 가동률 등)를 나란히 봐야 함

### 4.2 변경되는 워크플로우

```
현재:  idle → solving → review(1개) → approved
변경:  idle → solving(1~N) → comparing(N개 + 기존) → selecting → approved
```

### 4.3 비교 실행 모드

#### 모드 1: 단일 솔버 실행 (기존 유지)
- "스케줄 실행" 버튼: 선택한 솔버 1개만 실행
- 결과 1개가 비교 테이블에 추가됨

#### 모드 2: 전체 솔버 비교 실행 (신규)
- "전체 솔버 비교" 버튼: 5개 솔버 순차 실행
- OR_TOOLS → GA → SA → TABU → ALNS 순서
- 각 솔버 완료 시 결과가 비교 테이블에 즉시 추가됨
- 프로그레스바: "3/5 솔버 완료"

### 4.4 비교 테이블 UI

```
┌──────────────────────────────────────────────────────────────────────┐
│  스케줄 결과 비교                                    [결과 초기화]  │
├───────────┬──────────┬──────────┬──────────┬──────────┬──────────────┤
│  KPI      │ 기존스케줄│ OR_TOOLS │    GA    │    SA    │    TABU     │
├───────────┼──────────┼──────────┼──────────┼──────────┼──────────────┤
│ Makespan  │ 8h 30m   │ *7h 12m* │ 7h 45m   │ 8h 02m   │ 7h 38m      │
│ 가동률    │ 72%      │ *85%*    │ 82%      │ 78%      │ 80%         │
│ 작업 수   │ 15       │ 15       │ 15       │ 15       │ 15          │
│ 실행 시간 │ -        │ 12s      │ 8s       │ *3s*     │ 5s          │
│ 목적함수  │ -        │ *1250*   │ 1380     │ 1520     │ 1410        │
├───────────┼──────────┼──────────┼──────────┼──────────┼──────────────┤
│           │          │ [승인▶]  │ [승인▶]  │ [승인▶]  │ [승인▶]     │
└───────────┴──────────┴──────────┴──────────┴──────────┴──────────────┘
  * = 해당 KPI 최우수 값 (초록 하이라이트)
```

**비교 테이블 구성**:
- 첫 번째 열: 기존 스케줄 (현재 current-schedule API 데이터)
- 나머지 열: 각 솔버 실행 결과 (실행 순서대로 추가)
- 각 KPI 행에서 최우수 값 초록 하이라이트
- 각 결과 하단에 "승인" 버튼
- 상단 "결과 초기화" 버튼으로 비교 테이블 리셋

**비교 KPI 항목**:
| KPI | 설명 | 최우수 기준 |
|-----|------|-----------|
| Makespan | 전체 작업 완료 시간 | 최소 |
| 평균 가동률 | 설비 활용도 | 최대 |
| 스케줄 작업 수 | 배치된 작업 수 | 최대 |
| 실행 시간 | 솔버 연산 시간 | 최소 |
| 목적함수 값 | 솔버 최적화 목표값 | 최소 |

### 4.5 결과 선택 → 상세 검토 → 승인

1. 비교 테이블에서 원하는 결과의 "승인" 클릭
2. 해당 결과의 상세 뷰 표시 (기존 review 화면과 동일):
   - 스케줄 작업 테이블 (WO ID, 공정, 설비, 시작/종료)
   - 통계 카드 4개
3. 최종 확인 후 "스케줄 승인" 클릭
4. 작업지시에 반영

### 4.6 기존 스케줄 데이터 가져오기

비교 테이블의 "기존 스케줄" 열 데이터:
- `GET /api/v1/scheduler/current-schedule?date=오늘` 호출
- summary에서 설비 수, 작업 수 추출
- availability에서 slot 시간 계산하여 makespan 산출
- 가동률 = running_slots / total_slots

### 4.8 워크플로우 상태 변경

```
기존: "idle" | "solving" | "review" | "approving" | "approved"
변경: "idle" | "solving" | "comparing" | "detail" | "approving" | "approved"
```

- `solving`: 솔버 실행 중 (단일 또는 전체)
- `comparing`: 비교 테이블 표시 (결과 1개 이상)
- `detail`: 선택한 결과 상세 검토
- `approving/approved`: 기존과 동일
